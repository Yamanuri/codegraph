Why a graph database?

The short version, straight from the README.

A dependency ecosystem is a network, not a table. The questions worth asking about it — "what breaks if this package changes?", "how many hops separate these two libraries?", "which packages have a large blast radius but only one maintainer?" — are all variable-depth traversals over relationships.

In a relational database, each of those becomes a recursive common-table expression, and a query like "impact analysis to 3 hops, joined against a maintainer count" needs two of them stitched together. In CognoDB, they're single Cypher patterns: (dependent)-[:DEPENDS_ON*1..3]->(target) reads exactly like the question being asked, and performance stays proportional to the size of the traversal, not the size of the whole table.

The graph model also grows naturally: adding "which packages share a license" or "which developers have worked at the same organization" is a new pattern match, not a schema migration and a new set of joins.
